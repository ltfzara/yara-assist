# یارا — داشبورد چندفروشگاهی با Supabase

این نسخه ظاهر اصلی داشبورد را حفظ می‌کند و ورود/ثبت‌نام، پروفایل، چند فروشگاه برای هر حساب و ذخیره‌سازی ابریِ جداگانه برای هر فروشگاه را اضافه می‌کند.

## قابلیت‌ها

- ورود و ثبت‌نام با ایمیل و رمز عبور دقیقاً ۶ کاراکتری
- ورود مستقیم بعد از ثبت‌نام؛ اگر پاسخ ثبت‌نام نشست نداشته باشد، برنامه یک‌بار ورود با همان ایمیل و رمز را امتحان می‌کند. برای ورود بدون تأیید ایمیل، Email Confirmation باید در Supabase خاموش باشد.
- خروج امن و بازیابی نشست ورود در مراجعه بعدی
- بازیابی رمز عبور با ایمیل Supabase و فرم امن تعیین رمز جدید
- مدیریت فروشگاه‌ها از منوی کناری: ساخت، انتخاب و تغییر نام فروشگاه
- پروفایل قابل تکمیل با نام و شماره تماس
- ساخت و جابه‌جایی بین چند فروشگاه در یک حساب
- سفارش‌ها و دسته‌بندی‌های مستقل برای هر فروشگاه
- نمایش داشبورد خالی برای حساب/فروشگاه تازه؛ هیچ داده‌ای از localStorage مرورگر به حساب جدید وارد نمی‌شود
- ذخیره ابری سفارش‌ها و دسته‌بندی‌ها؛ خروج از حساب داده‌ها را حذف نمی‌کند
- حذف مشتری از دفترچه، همراه با حذف تمام سفارش‌های مرتبط همان مشتری در فروشگاه جاری
- توضیحات و کامنت‌های راهنما در بخش‌های اصلی منطق احراز هویت، فروشگاه‌ها و ذخیره‌سازی

## راه‌اندازی

1. از پروژه Supabase خود نسخه پشتیبان بگیر.
2. فایل `supabase/yara-preferred-ui-migration.sql` را کامل در SQL Editor پروژه اجرا کن.
3. در Supabase Dashboard به **Authentication → Providers → Email** برو و گزینه **Confirm email** را خاموش کن. در غیر این صورت Supabase تا تأیید ایمیل نشست فعال نمی‌دهد و ورود مستقیم پس از ثبت‌نام ممکن نیست.
4. در تنظیمات Password در Supabase، حداقل طول رمز را روی ۶ قرار بده (اگر تنظیمات پروژه حداقل بیشتری تحمیل می‌کند). رابط کاربری نیز رمز را دقیقاً ۶ کاراکتر می‌پذیرد.
5. در Supabase Dashboard به **Authentication → URL Configuration** برو و دامنه منتشرشده برنامه را به فهرست **Redirect URLs** اضافه کن؛ لینک بازیابی رمز به همین آدرس برمی‌گردد.
6. `index.html` را روی هاست وب خود منتشر کن.

## نکات دیتابیس و امنیت

- آدرس پروژه و publishable/anon key موجود در HTML برای استفاده مرورگر هستند؛ کلید service-role هرگز نباید در HTML قرار بگیرد.
- سیاست‌های RLS موجود جدول `orders` باید فعال بمانند و مالکیت را با `auth.uid() = user_id` محدود کنند.
- جدول‌های `businesses` و `profiles` در این migration با RLS محافظت می‌شوند. دسته‌بندی‌ها و سفارش‌ها علاوه بر `user_id` با `shop_id` فیلتر می‌شوند.
- migration برای سفارش‌ها و دسته‌بندی‌های قدیمی هر کاربر یک فروشگاه پیش‌فرض می‌سازد و داده‌های موجود را به آن وصل می‌کند.
- مشتری‌ها در مدل فعلی جدول مستقل ندارند؛ از سفارش‌ها استخراج می‌شوند. بنابراین حذف مشتری، سفارش‌های همان مشتری را از فروشگاه جاری حذف می‌کند. این عملیات برگشت‌ناپذیر است.
- رمز عبور شش‌کاراکتری امنیت پایین‌تری از رمز طولانی دارد. برای انتشار عمومی، فعال‌کردن محدودیت تلاش ورود، CAPTCHA و سیاست‌های ضد سوءاستفاده در Supabase توصیه می‌شود.

## ساختار

- `index.html`: رابط کاربری، احراز هویت، پروفایل و مدیریت فروشگاه‌ها
- `supabase/yara-preferred-ui-migration.sql`: جداول، triggerها، ایندکس‌ها و سیاست‌های RLS موردنیاز
